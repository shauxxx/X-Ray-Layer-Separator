# PCB Layer Separation: разделение работы и план

Проект: приложение на Python для разделения томографических (DTS) снимков печатных плат на слои. Часть большого проекта по обратной разработке плат. Команда из 4 человек, срок 1 семестр.

## Входные данные

Цифровой томосинтез (DTS), по сути ротационная ламинография. Источник вращается вокруг горизонтально лежащей платы, лучи идут наклонно.

| Параметр | Значение |
|---|---|
| Установка | Eltech-XRay, приёмник 1215CG |
| Проекций | 36 (PNG, 16 бит) |
| Шаг поворота | 10°, полный оборот 360°, направление CW |
| Размер кадра | 2280 x 1812 px |
| Размер пикселя | 64 мкм (с учётом масштаба 113.348 мкм) |
| Object to Source | 131.69 мм |
| Camera to Source | 237.64 мм |
| Angle | 32.43 |
| Delta Z | 2.48926 |
| Коррекции | Flat Field, Defect Map, Offset: включены |

Следствия:
- Проекций мало, углы неполные, поэтому слои по Z будут частично размыты. Это ожидаемо для томосинтеза.
- Для каждой высоты z строится срез, на котором резкими выглядят только элементы с этой высоты.
- Геометрия берётся из лог-файла, нужен парсер.

Открытые вопросы к ментору или документации Eltech:
- Что именно означают `Angle` (угол наклона оси пучка?) и `Delta Z` (шаг между срезами, мм?).
- Направления осей и положение начала координат.

## Структура репозитория

```
pcb-layer-separation/
├── src/pcblayers/
│   ├── io/             # парсер лога, загрузка PNG-проекций, экспорт
│   ├── geometry/       # модель установки, проекционная матрица
│   ├── preprocess/     # нормализация, шумоподавление, регистрация
│   ├── reconstruction/ # shift-and-add, FBP-подобный, SART
│   ├── segmentation/   # выделение слоёв платы, очистка артефактов
│   └── ui/             # CLI + просмотрщик слоёв
├── tests/
├── examples/
├── docs/
└── pyproject.toml
```

Конвейер: **лог + PNG -> предобработка -> реконструкция срезов по Z -> разделение на слои меди/компонентов -> экспорт (PNG/TIFF, стек)**.

## Разделение на 4 человека

### 1. Данные, геометрия и ядро (тимлид)
- Парсер лога в dataclass `ScanConfig`, загрузка 16-битных PNG-проекций.
- Геометрическая модель: положение источника для каждой из 36 проекций (угол поворота, наклон 32.43°, расстояния, масштаб пикселя).
- Общие интерфейсы между модулями, структура репозитория, CI, `pyproject.toml`, README.
- Синтетический тестовый набор: смоделировать проекции известной «платы», чтобы проверять реконструкцию без реальных данных.

### 2. Предобработка проекций
- Нормализация яркости, логарифмирование (закон Бугера, `-log(I/I0)`).
- Шумоподавление (аппаратные flat-field, defect map и offset в логе уже включены).
- Учёт `DetectorShifts` (Left=4).
- Регистрация проекций между собой, если есть смещения.
- Метрики качества и визуальная проверка (гистограммы, сравнение до/после).

### 3. Реконструкция по слоям (самый сложный блок)
- Базовый алгоритм: **shift-and-add** (быстро, наглядно, хорошая основа для сдачи).
- Улучшенный: фильтрованная обратная проекция и/или итеративный SART.
- Подавление размытия соседних слоёв по Z (deblurring).
- Ускорение (NumPy/Numba/GPU), выбор шага по Z (Delta Z).
- Сравнение алгоритмов по качеству и времени.

### 4. Разделение на слои, интерфейс и документация
- Анализ стека срезов: поиск высот с максимальной резкостью/контрастом (focus measure по z), чтобы определить, где лежат реальные слои платы.
- Сегментация медных дорожек, переходных отверстий и компонентов на каждом слое.
- Экспорт результата (слои как изображения, стек TIFF).
- Интерфейс: CLI (`pcblayers reconstruct --log scan.ini --input ./png`) и простой просмотрщик слоёв.
- Документация, примеры, демо для защиты.

## Зависимости между блоками

| Кто | Что отдаёт | Кому |
|---|---|---|
| 1 | `ScanConfig`, загрузчик проекций, синтетические данные | всем |
| 2 | очищенный стек проекций | 3 |
| 3 | стек срезов по Z | 4 |
| 4 | слои и экспорт, интерфейс | пользователю |

Формат обмена между модулями фиксируется в первую неделю: `numpy`-массивы + `ScanConfig`.

## План на семестр

| Недели | Что делаем |
|---|---|
| 1-2 | Разбор данных и геометрии, структура репозитория, парсер лога, синтетические данные |

| 10-12 | Интерфейс, оптимизация, тесты |

## Правила работы в репозитории

- Отдельная ветка на каждого участника, merge через pull request с ревью от другого участника.
- Реальные снимки в репозиторий не коммитим: храним в `data/` из `.gitignore` или отдельным хранилищем со ссылкой.
- Тесты на синтетических данных обязательны для каждого модуля.
