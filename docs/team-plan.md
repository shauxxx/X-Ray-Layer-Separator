# PCB Layer Separation: разделение работы и план

Проект: приложение на Python, которое берёт GIF-анимацию, собранную из томографических (DTS) проекций печатной платы, и разделяет её на два слоя. Часть большого проекта по обратной разработке плат. Команда из 4 человек, срок 1 семестр.

## Идея решения

Кадры сняты под разными углами, поэтому слои платы, лежащие на разной высоте, смещаются между кадрами по-разному. Нижний слой при этом остаётся относительно стабильным, а верхний движется. Задача программы: измерить смещения между кадрами, использовать их, чтобы отделить неподвижную составляющую от движущейся, и восстановить два изображения: `layer_1.png` и `layer_2.png`.

Конвейер: **GIF -> кадры NumPy -> смещения (Δx, Δy) -> разделение и реконструкция -> layer_1.png, layer_2.png**.

## Справка об исходной съёмке

Данные получены на установке Eltech-XRay, режим цифрового томосинтеза (DTS). Параметры из лога пригодятся для проверки адекватности результатов, например для оценки ожидаемой величины смещений.

| Параметр | Значение |
|---|---|
| Проекций | 36 (PNG, 16 бит) |
| Шаг поворота | 10°, полный оборот 360°, направление CW |
| Размер кадра | 2280 x 1812 px |
| Размер пикселя | 64 мкм (с учётом масштаба 113.348 мкм) |
| Object to Source | 131.69 мм |
| Camera to Source | 237.64 мм |
| Angle | 32.43 |
| Delta Z | 2.48926 |
| Коррекции | Flat Field, Defect Map, Offset: включены |

Риск: GIF хранит не более 256 цветов на кадр, а исходные проекции 16-битные. При конвертации в GIF теряется динамический диапазон, что снижает точность оценки смещений и качество разделения. Стоит заранее уточнить, как именно получается GIF (масштабирование, нормализация яркости), и при возможности дополнительно поддержать загрузку последовательности PNG.

## Разделение на 4 человека

### Участник 1. Загрузка и подготовка GIF
**Модуль 1.** Файлы: `gif_loader.py`, `preprocessing.py`.

- Извлекать все кадры GIF через Pillow.
- Приводить кадры к единому формату и размеру.
- Проверять FPS, количество кадров, разрешение.
- Подготавливать изображения для дальнейшего анализа.
- Сохранять промежуточные кадры для отладки.

**Результат:** список кадров NumPy одинакового формата.

### Участник 2. Анализ движения
**Модуль 2.** Файл: `motion_analysis.py`.

- Измерять двумерное смещение между кадрами.
- Проверять стабильность нижнего слоя.
- Оценивать траекторию движения верхнего слоя.
- Визуализировать смещения на графике.
- Определять кадры, в которых оценка ненадёжна.

**Результат:** векторы смещения (Δx, Δy) для каждого кадра.

### Участник 3. Разделение и реконструкция
**Модуль 3.** Файлы: `layer_separation.py`, `reconstruction.py`.

- Реализовать алгоритм разделения неподвижной и движущейся составляющих.
- Использовать смещения, полученные участником 2.
- Объединять информацию из нескольких кадров.
- Снижать шум и артефакты.
- Сохранять результат в `layer_1.png` и `layer_2.png`.

**Результат:** алгоритм восстановления двух изображений.

### Участник 4. Интеграция и тестирование
**Модуль 4.** Файлы: `main.py`, `tests/`.

- Объединить модули в единый конвейер.
- Реализовать запуск программы из командной строки.
- Проверять работу на разных GIF.
- Сравнивать результат с исходными кадрами.
- Настроить зависимости и инструкции запуска в README.

**Результат:** программа, которую можно запустить одной командой.

## Интерфейсы между модулями

Эти контракты стоит зафиксировать в первую неделю, чтобы модули собирались без переделок.

| От кого | К кому | Формат данных |
|---|---|---|
| Участник 1 | 2 и 3 | `list[np.ndarray]`: кадры одного размера и типа (например, `float32` в диапазоне 0..1, один канал) |
| Участник 2 | 3 | `np.ndarray` формы `(N, 2)` с (Δx, Δy) на каждый кадр, плюс маска или флаги надёжности кадров формы `(N,)` |
| Участник 3 | 4 | два массива `layer_1`, `layer_2`, записанные в `layer_1.png` и `layer_2.png` |
| Участник 4 | всем | `main.py` вызывает модули по этим контрактам |

## Как работать параллельно

Блоки зависят друг от друга по данным, но начинать можно одновременно:

- Участник 1 в первые дни отдаёт «заглушку»: функцию, которая возвращает кадры из тестового GIF, пусть даже без финальной подготовки.
- Участник 2 разрабатывает алгоритм на синтетических кадрах (картинка, сдвинутая на известные значения), где правильный ответ известен заранее.
- Участник 3 тоже начинает с синтетики: два наложенных изображения, одно неподвижное, другое движется с известными смещениями.
- Участник 4 собирает каркас `main.py` и тесты на заглушках, а потом подставляет настоящие модули.

## План на семестр

| Недели | Что делаем |
|---|---|
| 1-2 | Согласовать интерфейсы, структура репозитория, загрузка GIF, синтетические тестовые данные, каркас `main.py` |
| 3-5 | Предобработка кадров, первая оценка смещений, базовое разделение слоёв на синтетике |
| 6-9 | Надёжность оценки смещений, объединение кадров, шумоподавление, первые результаты на реальных GIF |
| 10-12 | Интеграция всего конвейера, CLI, сравнение результата с исходными кадрами, тесты |
| 13-15 | Доработка качества, README и инструкция запуска, финальная проверка, подготовка к защите |

## Правила работы в репозитории

- Отдельная ветка на каждого участника, слияние через pull request с ревью от другого участника.
- Большие GIF и реальные снимки в репозиторий не коммитим: храним вне репозитория или в `examples/` только небольшие тестовые.
- Каждый модуль сопровождается тестами в `tests/` (синтетические данные с известным ответом).
- Отладочные кадры и результаты складываем в `output/` и добавляем в `.gitignore`.
